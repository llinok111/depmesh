# 分析覆盖范围（明确声明）

这份文档回答一个问题：**这个图谱到底覆盖了什么，没覆盖什么。**
运行时同一份内容在 `depmesh coverage` 的文本输出与页面的覆盖面板里都能看到。

## 1. 覆盖范围的三个维度

### 文件维度

| 项 | 含义 |
| --- | --- |
| 已发现 | 在 roots 下、扩展名命中、未被 `--exclude` 命中的文件 |
| 已解析 | 被成功读取并交给解析器的文件 |
| 解析失败 | 语法错误（用 TypeScript 解析器的 `parseDiagnostics` 判定），**该文件不产生任何出边** |
| 跳过 | 扩展名不命中 / 目录为 `node_modules` 或 `.git` / 被排除规则命中，**计数但不分析** |

### 说明符维度

| 项 | 含义 |
| --- | --- |
| 已提取 | 解析器从源文件里读出的 import / export-from / require / dynamic import 字符串 |
| 解析到项目内 | 命中本仓库文件，成为边 |
| 解析到第三方包 | 命中 `node_modules` 且不在 roots 内，**计数但不展开** |
| 未解析 | 解析器返回空或返回不存在的路径，**只进报告，绝不进边集** |

### 边维度

一条 `from -> to` 边要求同时满足：说明符在 `from` 里逐字存在（解析器提取的）、
`to` 在磁盘上存在、`to` 不是被排除的第三方包。三条缺一不进图。

## 2. 内置语料实测（vue-core 3.5.44，`packages/<pkg>/src`）

| 指标 | 值 |
| --- | --- |
| 扫描文件 | 234 |
| 解析成功 | 234（100%） |
| 解析失败 | 0 |
| 说明符总数 | 1320 |
| 解析到项目内 | 1259 |
| 解析到第三方包 | 31（8 个包，不展开） |
| 未解析 | 30（全部是未安装的包） |
| 内部解析率 | 97.67%（分母 = 项目内 1259 + 失败 30） |
| 边数 | 1185 |
| 其中 type-only 边 | 212（可用 `--no-type-edges` 去掉） |

未解析的 30 条全部是 `missing-package`，例如：

- `compiler-core/src/ast.ts -> @babel/types`
- `compiler-core/src/babelUtils.ts -> estree-walker`
- `compiler-core/src/parser.ts -> entities/decode`

这些包在 vue 的 `devDependencies` 里，本仓库没有安装它们，所以它们的内部结构不可知。
报告里不会用猜测补上，也不会影响其余 1185 条边的可信度。

## 3. 第二个语料（大型 CommonJS 树）

`node_modules/eslint/lib`（eslint 7.29，376 个 `.js` 文件）：

| 指标 | 值 |
| --- | --- |
| 模块 | 376 |
| 边 | 572 |
| 外部包 | 38 |
| 未解析 | 0 |
| 环分量 | 0（该目录是有向无环的） |
| 扫描耗时 | 约 2.6 s（本机，含首次文件缓存未命中） |

这个语料的作用是证明"非 TS、纯 CommonJS、规模更大"的项目同样能跑通，
并且 `node_modules` 内的语料不会被误判成"全部外部依赖"（有专门用例覆盖）。

## 4. 明确不覆盖的内容

1. **动态路径导入**：`require(someVariable)`、`import(prefix + name)` 静态不可知，一律缺失。
2. **未被白名单命中的扩展名**：默认 `js,jsx,mjs,cjs,ts,tsx`；`.vue`、`.svelte`、`.json`、`.d.ts` 不是节点。
3. **第三方包内部**：只统计被引用的包名与次数，不展开 `node_modules` 里的模块图。
4. **类型系统信息**：不做类型检查，不做 `tsconfig` 的 `exclude`/`include` 语义裁剪（只有 `paths` 参与解析）。
5. **运行时行为**：不执行代码，因此条件导入（`if (dev) require(...)`）按静态出现计入。
6. **`node:` 与 Node 内置模块**：解析器按上游设定 `includeCore: false` 直接丢弃，不进报告。
7. **符号级关系**：只有文件级依赖，没有"函数 A 调用函数 B"。

## 5. 可信度如何自证

| 性质 | 验证方式 | 结果 |
| --- | --- | --- |
| 边不是编的 | 逐边断言说明符在源文件中逐字出现 | 1185/1185 通过 |
| 边目标真实 | 逐边 `existsSync` | 1185/1185 通过 |
| 与上游解析一致 | 与 madge 在同一语料上比对边集 | 1185 vs 1185，双向差异 0 |
| 环不漏 | 与独立"可达自身"BFS 判据比对 | 128 vs 128 完全相同 |
| 环是真的 | 每条示例环逐边校验闭合 | 全部 `verified: true` |
| 影响面正确 | 与独立反向 BFS 重算比对 | 完全一致 |
| 预算不撒谎 | 超预算时返回 `truncated: true` + 原因 | 有用例锁定 |
| 语法错误不被吞 | 故意写坏的文件被标为未解析 | 有用例锁定 |
