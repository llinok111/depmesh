# 已知限制

限制分三类：**静态分析本身的**、**本实现选择造成的**、**环境造成的**。
前两类在 `depmesh coverage` 的输出里也会出现，不做隐藏。

## 1. 静态分析固有的

| 限制 | 说明 | 是否可补 |
| --- | --- | --- |
| 动态路径导入 | `require(variable)`、`import(base + x)`、`require.resolve` 拼接，静态不可知 | 需运行期插桩，不在本工具范围 |
| 条件导入 | `if (process.env.DEV) require('./debug')` 一律按静态出现计入 | 需要环境感知，代价高、收益低 |
| 重导出链的语义 | `export * from './x'` 记为一条边，但不展开"实际暴露了哪些符号" | 属符号级分析 |
| `.vue` / `.svelte` / `.json` | 默认扩展名不包含，不是节点 | 可加检测器，未纳入 |
| 类型擦除 | 只按语法形态标注 `type`，不做类型解析 | 属类型系统范畴 |

## 2. 本实现的选择

| 选择 | 后果 | 为什么这么选 |
| --- | --- | --- |
| 第三方包不展开 | 跨包边界在 `node_modules` 处截断，图中看不到包内部结构 | 项目图的价值是"我的代码怎么连"，展开三方会把图淹掉 |
| 环的示例最多 3 条/分量 | 大分量里只展示少量代表环 | 全量初等环指数级；分量本身（SCC）已是精确答案 |
| 路径枚举有预算 | `maxPaths` / `maxLength` / `maxExpansions` 触发时返回 `truncated: true` | 稠密图全路径不可枚举，宁可承认截断 |
| 影响面默认 4000 节点上限 | 超大图会截断，`truncated` 会置位 | 防止 10 万节点的图把浏览器卡死 |
| 语法错误用 TypeScript 解析器判定 | 非 TS 支持的扩展名不判定（返回 0） | 不猜；JSX/TS 语法以 TS 5.4 为准 |
| type-only 边默认保留 | 影响面会略偏大 | 类型改动同样需要改下游；可用 `--no-type-edges` 关掉 |
| 单文件 HTML 内联全部数据 | 超大图（>1 万节点）页面体积会到十几 MB | 换取"离线、无服务、可直接分享" |

## 3. 环境造成的

| 现象 | 原因 | 影响 |
| --- | --- | --- |
| `npm run lint` 全红 | 本机 `core.autocrlf=true`，工作区是 CRLF，而上游 eslint 规则要求 LF | 与 depmesh 无关；`git config core.autocrlf false` 后重检即为绿色。新增模块另用 `.eslintignore` 隔离，不会让上游 lint 变红 |
| 上游 mocha 有 6 条失败 | 5 条缺 Graphviz（`gvpr`），1 条路径分隔符断言不可移植 | 上游既有问题，记录在 `docs/UPSTREAM-FINDINGS.md` 第 5 节 |
| 首次扫描较慢 | precinct 与 filing-cabinet 的解析缓存未预热 | 第二次同语料明显变快（vue-core 7.7s → 3.5s） |

## 4. 不适合的场景

- **需要符号级依赖**（谁调用了谁的哪个函数）：本工具只到文件级。
- **需要在 CI 里卡门禁**：可以（退出码 1 表示存在未解析导入），但不要拿"边数与上次不同"当唯一判据，
  依赖升级会改变解析结果。
- **超大单体仓库（>2 万文件）**：默认 `--max-files 5000` 会直接拒绝；需要调高，并接受分钟级耗时。
